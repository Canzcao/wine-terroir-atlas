## Daily work

1. Read the existing datasets, recent event history and current date before searching. Read Sites building/hosting instructions and call get_site before editing this existing Site.
2. Search multiple countries/continents. Prefer wineries, regional associations, universities, meteorological or civil protection agencies, and event organizers. Start with new publications since last checked date; upcoming events may extend 60 days. Open primary pages and confirm the facts and dates. Do not treat search snippets as verification. Search news and natural-disaster categories each run, but do not create items merely to fill a category.
3. Update `data/events.json`. Preserve stable IDs. Deduplicate by event subject, dates and location, not just URLs. Keep occurrence dates separate from source publication and retrieval dates. Unknown end/publication dates are null. Cancellation and corrections update the original item; record previous values plus reason/source/check time in `data/event-history.json`. Use short original Chinese summaries, never full copied articles.
4. Each event requires source URL/name, checked date, verification description, country/region, coordinates and explicit location precision. Use an evidenced location or clearly identified region/town representative point. Never invent parcel boundaries, ownership, planting data, precise disaster footprints, casualty counts or ongoing alert status. Forecasts and agricultural observations are `weather`; confirmed disasters are `disaster`. If facts are uncertain, omit or attribute them explicitly, and do not mark them independently verified.
5. Every day actively search for wineries not yet in the catalogue and new information about known wineries, independently of the news search. “New” means newly discovered for this map, not necessarily recently founded. Search countries/regions in rotation and check the wineries' own wine pages. Deduplicate by official domain, names/aliases, country and address before adding records. Add useful verified discoveries to `data/catalog-seed.json` with stable IDs and original sources. Store winery `data.locationSourceURL`, `data.locationPrecision`, address and checkedDate when available. Coordinates must identify an evidenced winery/estate/visitor location: never use the center of a map viewport, corporate headquarters or a grape-source region as a winery location. Label a tasting-room location explicitly. Leave unverified coordinates null. A wine points to `wineryId`; its vintage points to `wineId`, with composition specific to the vintage where applicable. Reuse existing IDs. All wines and vintages appear at their winery's same map marker, never at invented independent coordinates. Known-region fallback is explicitly approximate and does not create a persistent winery pin. Production D1 overrides and community records take precedence; do not overwrite or reset them. Do not rerun `seed.mjs` or `add-initial-wines.mjs`; they were one-time bootstrap scripts.
6. Work through the selected region's official producer list and each producer's public wine catalogue without an arbitrary five-record cap. Record the coverage denominator, checked and outstanding entries so the next run can resume, but do not turn that into a progress-report deliverable. A completed source list is not a claim of complete knowledge of the entire web. Keep old events as history. Collect geography first: a winery without evidenced coordinates does not appear on the map at all. Label gaps honestly.
7. Run `node scripts/validate-data.mjs` and `node scripts/validate-reports.mjs`, then the Sites build wrapper. For data-only changes, do not modify schema/migrations or repeat unrelated UI tests. Commit and push exact source with a short-lived credential kept only in memory, package with the Sites helper and deploy to the same current audience. Verify terminal deployment success. Do not change runtime OWNER_EMAIL or membership. Never expose credentials.
8. On a source outage, record the unverified item and continue elsewhere; do not count it as completed. On deployment failure keep the current live version intact, report the actionable issue and do not claim the update went live. Deliver the collection bundle to this task every day in the shape defined by `采集规格-网站字段对照.md` (`outputs/collect/YYYY-MM-DD/`: catalogue additions, event additions, geo results including failures, licensed images with attribution, sources, and a handoff note for the explainer conversation), plus a zip of the period's collected material. Licensed photographs and their attribution manifest are collected as Site assets under DAILY_EDITORIAL.md's image rules; do not send emails or messages to other people.

## Structure

- `public/`: existing map, community and catalogue UI. `worker/`: Cloudflare Worker APIs; D1 and R2 store durable submissions, members, published versions and attachments.

**Image policy (2026-09-13).** Public images on producer and regional-association websites may be collected and used without a pre-existing commercial licence, because the Site carries a "合作上传，如侵权可联系删除" notice and its owner handles claims. Never strip watermarks, never upscale, never pass generated images off as real vineyards, wines or events, and never claim ownership. Every collected image must keep source page, direct file URL, retrieval time, byte size, SHA-256 and true pixel dimensions so any single image can be located and removed on request; store images per winery so one producer can be removed wholesale. Collect politely: rate-limit per host, honour robots.txt and its Crawl-delay, and take only images the content actually uses. Open-licence images (e.g. Wikimedia Commons) additionally keep author and licence link.

**Image targets (2026-09-13).** Two kinds of picture are collected for every producer, because the Site needs both: pictures of the *people and place* (the winemaker, the team, the cellar, the vineyard — the association directory page carries up to six of these per estate in a lightbox gallery whose URLs live only in generated CSS), and pictures of *the wines the estate makes* (bottle packshots, label artwork, cuvées, magnums — reached by following the estate's own website, whose address the directory exposes behind the "ACCÉDER AU SITE" button).

Never let a filename keyword stand in for a look at the picture. `Vignobles-Levet1.png` is a real bottle with no keyword in its name; `front-view-wine-glasses-...` is a stock photo that does contain one. So every image carries `role`, `confidence`, `attribution` and the `reasons` behind the call; uncertain ones are queued with `reviewAs`, and a visual pass (contact sheets → verdicts → `classificationMethod: agent-visual-review`) settles what the heuristics could not. Wine images must also carry the *appellation read off the bottle*, so a Côte-Rôtie bottle is never filed as a Condrieu wine.
- `db/schema.ts` and `drizzle/`: schema-only generated migrations. Applied migrations are immutable.
- `data/catalog-seed.json`: initial/curated sourced catalogue, merged with production community changes. `data/events.json`: daily editorial event feed. `data/event-history.json`: editorial corrections.
- `npm run build` embeds static assets into `dist/server/index.js`. `npm run dev` is a local-only preview with a test identity injected by a proxy; this proxy is never deployed. `npm test` runs isolated real D1/R2 emulation for authorization and publishing conflicts.
- Every write API checks identity, membership and origin. Never add a public admin switch or frontend-only authorization. Production owner bootstrap uses the runtime secret OWNER_EMAIL and the platform-asserted signed-in identity.

## 资料语言与翻译

酒庄、酒款资料优先完善其所在国的本地语言和英语；中国酒庄先完成中文与英文。对多语言国家，按酒庄实际使用的原文语种优先，明确可核实的其他本地语言再补充。界面语种与资料语种分开：界面切换不构成实体译文的证据。

每条酒庄/酒款记录的 `data.originalLanguage` 记录已知原文语种；`data.localizations[语种]` 分别保存 `name`、`description`、`sourceURL`、`sourceTitle`、`checkedDate` 和 `status`。只有官方对应语种页面、权威术语来源或经人工核对的有据译文，才可标记 `verified` 并公开展示；未知、不确定或未经核对的译文保留空白或 `draft`。不批量猜译专有名词，不把旧 `en` 原文名称字段当作已确认英文。保留品牌原名；没有可靠对应译文时回退已有本国语言/英文或原文，并明确标记实际显示语种。中文日报仍按原有中文发布，除非另有已核对译文。

每次采编先检查本期酒庄与酒款的本国语言/英语缺口，优先补齐有来源的名称与简介。记录来源日期，保留既有语种、稳定ID、地图位置与数据库覆盖优先级，不用新的单一语种资料覆盖其他已核对语种。报告如实说明补齐多少条及仍缺哪些语种。
